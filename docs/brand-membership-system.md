# NIHPLOD 品牌会员体系书

版本：V1.0（团队讨论稿）  
适用范围：NIHPLOD 官网、官方商城、AI 测肤子站、授权线上渠道与线下门店  
文档口径：标注“现行”的内容已与当前主站实现一致；标注“待决策/规划”的内容不代表已经上线。

## 1. 体系定位

NIHPLOD 会员体系以“理解肌肤、持续护理、透明回馈”为核心，不只是一个折扣体系。

会员关系由三部分组成：

1. **会员身份**：用户注册、账户安全及跨渠道统一识别。
2. **会员等级**：反映用户在官方及授权渠道的累计净消费，决定当前权益。
3. **会员积分**：记录消费、生日及持续护理行为，用于兑换品牌礼品和服务。

### 设计原则

- 规则可理解：用户能看懂如何升级、积分何时到期、退款有什么影响。
- 权益可兑现：展示的权益必须有对应系统能力和运营负责人。
- 账本可追溯：消费、积分、等级变化和兑换均可审计。
- 风险可持续：礼遇成本、退款和套利必须纳入产品设计。
- 隐私有边界：会员存续与“永久保留”宣传不得绕过注销和数据删除规则。

## 2. 名词与统一口径

| 名词         | 定义                                                       |
| ------------ | ---------------------------------------------------------- |
| 注册会员     | 完成 NIHPLOD 账户注册的用户，默认普通会员                  |
| 累计净消费   | 已核实消费金额扣除退款、撤销和冲正后的金额                 |
| 当前等级     | 按当前累计净消费实时计算的会员等级                         |
| 积分余额     | 积分账本中的可用余额；退款超兑时可能为负数                 |
| 积分到期     | 自对应发放流水起计算有效期，到期未使用部分自动作废         |
| 履约保护期   | 兑换订单创建后 7 天内不安排发货的风险控制窗口              |
| 会员存续期间 | 账户保持有效且未注销的期间；注销后按隐私及注销规则处理数据 |

“无固定到期日”不等于“永久不降档”。当前等级会随累计净消费上升或下降。

## 3. 会员等级

### 3.1 现行等级门槛

| 等级               | 累计净消费门槛 | 核心定位                             |
| ------------------ | -------------: | ------------------------------------ |
| 普通会员 REGULAR   |     注册即加入 | 测肤体验、消费积分、升级引导         |
| 银卡会员 SILVER    |         ¥1,000 | 解锁积分兑礼、生日礼遇及更多测肤额度 |
| 金卡会员 GOLD      |         ¥5,000 | 累计不限量测肤、更优兑礼倍率         |
| 钻石卡会员 DIAMOND |        ¥10,000 | 当前最高等级、最优兑礼倍率和生日积分 |

### 3.2 现行升级与降档规则

- 消费经核实入账后立即重算等级。
- 退款、撤销或冲正减少累计净消费，并立即重算等级。
- 等级没有固定到期日，但会因累计净消费变化而升档或降档。
- 当前权益跟随当前等级；历史兑换保留兑换时的等级与兑礼率快照。
- 系统记录等级变更轨迹，供客服核查。

### 3.3 推荐用户文案

> 会员等级按官方及授权渠道的累计净消费实时判定，无固定到期日。退款或冲正会减少累计净消费，等级及当前权益可能随调整后的金额变化。

## 4. 权益体系

### 4.1 现行权益对比

| 权益         | 普通                 | 银卡                 | 金卡           | 钻石           |
| ------------ | -------------------- | -------------------- | -------------- | -------------- |
| AI 测肤      | 注册共 10 次         | 每满 ¥1,000 加 20 次 | 累计不限量     | 累计不限量     |
| 每日测肤上限 | 以子站当前配额为准   | 每日最多 10 次       | 每日最多 10 次 | 每日最多 10 次 |
| 肌肤档案     | 按账户及隐私规则保存 | 会员存续期间持续保留 | 同银卡         | 同银卡         |
| AI 护肤顾问  | 基础体验             | 专属顾问服务         | 专属顾问服务   | 专属顾问服务   |
| 消费积分     | 1 元 = 1 分          | 1 元 = 1 分          | 1 元 = 1 分    | 1 元 = 1 分    |
| 积分兑礼     | 不可兑换，可累积     | 开放                 | 开放           | 开放           |
| 兑礼折算率   | —                    | 1                    | 1.3            | 1.5            |
| 每年生日积分 | 0                    | 50                   | 100            | 200            |

“累计不限量”不等于每日无限使用；每日限制用于控制服务质量、成本和滥用。

### 4.2 兑礼率的统一解释

兑换积分按以下公式计算：

> 所需积分 = max(1，向下取整〔礼品参考价 ÷ 当前等级兑礼率〕)

例如，参考价 ¥300 的礼品：

- 银卡：300 积分；
- 金卡：向下取整 300 ÷ 1.3，即 230 积分；
- 钻石：300 ÷ 1.5，即 200 积分。

用户确认前应看到实际扣分；等级或参考价变化时，必须重新确认，不得静默按新价格扣分。

## 5. 积分规则

### 5.1 现行积分来源

| 来源     | 规则                                                                |
| -------- | ------------------------------------------------------------------- |
| 消费     | 核实消费每 1 元发放 1 积分，所有等级均可累积                        |
| 生日     | 银卡 50、金卡 100、钻石 200，每年最多一次                           |
| 测肤打卡 | 当日首次手动打卡按连续天数奖励 1/2/3 分，连续第 3 天及以后每日 3 分 |
| 人工调整 | 仅用于有工单依据的客服补偿或冲正，并保留审计                        |
| 兑换退分 | 取消或售后完成后按原兑换实际扣分退回                                |

### 5.2 有效期与使用顺序

- 积分自对应发放流水起 6 个月内有效。
- 消费积分即时显示并计入余额；兑换订单另有 7 天履约保护期。
- 使用时按先进先出原则消耗最旧的有效积分。
- 过期只处理对应流水剩余未消耗部分。
- 普通会员可以累积积分，但只有银卡及以上可以使用积分兑换；积分有效期不会因升级自动顺延。
- 用户应能看到近期积分明细及到期提醒。

### 5.3 退款与负积分

- 消费退款会冲减对应消费额、积分及重新计算等级。
- 若积分已经使用，退款后余额可以为负数。
- 负积分表示后续需要优先抵扣的积分差额，不是现金欠款。
- 负余额账户不能继续兑换；已有待履约订单须先完成核查或取消。
- 已发货或已完成订单发生退款时，仍需人工核查赠品与售后责任，不能仅依赖积分账本自动解决。

## 6. 兑换与履约保护

### 6.1 本次已生效的保护规则

1. 用户确认兑换后，积分立即扣减并生成待履约订单。
2. 自兑换时刻起进入完整 7×24 小时保护期，不按自然日清零。
3. 保护期内管理端不能标记发货。
4. 页面展示预计可履约时间；管理端按钮和接口同时受限。
5. 保护期届满后仍需通过账户状态、积分余额及订单状态检查才能履约。
6. 待履约订单可以按现有流程取消；售后退货按审核结果退分。

### 7 天保护期的目的

- 给消费退款、误操作和异常订单留出核查时间。
- 降低“消费后立即兑礼、再退款”的赠品成本风险。
- 让客服在用户催促发货时有统一、可解释的口径。

保护期是风险缓解措施，不替代反欺诈审核，也不能消除所有售后损失。

## 7. 生日礼遇

### 现行规则

- 生日由用户首次设置后锁定，修改需客服核验。
- 银卡及以上每年最多发放一次。
- 每日任务支持最近 7 天生日宽限补发。
- 当前实现按实际发放任务执行时的等级计算金额，并记录年度幂等键。
- 生日积分同样具有 6 个月有效期。

### 待团队确认

- 是否将“按生日当天等级”改为“按实际入账日等级”，使文案与技术完全一致。
- 2 月 29 日生日在非闰年应固定于 2 月 28 日还是 3 月 1 日发放。
- 是否需要生日前提醒和生日积分到账通知。

## 8. 跨渠道会员身份与数据连续性

- 官网账户是会员等级、累计净消费和积分账本的权威来源。
- 微信、小程序及其他第三方身份只用于统一识别，不应重复创造会员资产。
- 重复账户合并时必须预检账本、订单、身份和子站冲突；源账户会话及授权撤销，目标账户密码不变。
- 换绑手机号不等于更换会员，历史消费和积分保留。
- 账户注销后积分作废，子站数据按注销流程清除；营销中的“长期保留”不得突破用户注销权。

## 9. 用户旅程

### 9.1 注册与首次体验

注册 → 普通会员 → 获得测肤体验 → 形成肌肤档案 → 引导完善资料和了解会员规则。

### 9.2 消费升级

官方/授权渠道消费 → 自动同步或提交补录 → 人工核实（如需）→ 累计净消费和积分入账 → 实时升级 → 解锁权益。

### 9.3 积分兑换

查看实际所需积分 → 选择收货地址 → 二次确认 → 扣积分 → 进入 7 天保护期 → 查看预计履约时间 → 发货与物流 → 确认收货/售后。

### 9.4 退款降档

退款入账 → 冲减累计净消费和积分 → 重算等级 → 核查待履约订单及负积分 → 向用户解释权益变化。

## 10. 管理与风控要求

- 消费补录必须核实订单归属，防止同一订单跨渠道、跨账户重复入账。
- 积分调整、取消兑换和售后退分必须具备权限、二次验证、原因及审计。
- 管理端应能处理资料纠错、地址纠错、售后、设备和账户异常，避免要求用户重复操作。
- 对账至少覆盖积分余额与流水、兑换与退分、累计消费与消费流水、订单占用和退款冲突。
- 规则变更必须评估存量会员影响，不应直接修改生产数值而不做重算和通知。

## 11. 运营指标

建议按周/月建立以下指标：

### 会员增长

- 注册人数及各等级人数；
- 普通→银卡、银卡→金卡、金卡→钻石转化率；
- 达到下一门槛所需金额分布；
- 升级后 30/90 天复购率与留存率。

### 积分经营

- 消费、生日、打卡、补偿分别发放多少积分；
- 积分兑换率、过期率、负余额人数及金额；
- 各等级积分消耗与兑换礼品结构；
- 保护期内取消率、退款率和异常订单率。

### 权益成本

- 测肤次数、使用率和单次成本；
- 礼品采购及履约成本；
- 退款后已交付礼品成本；
- 各等级收入、权益成本与贡献毛利。

## 12. 待讨论与后续路线

### P0：规则与合规持续评审

- 法务复核会员规则、隐私政策及客服话术的一致性。
- 财务确认 7 天保护期是否足以覆盖主要退款场景。
- 明确普通会员“可累积但暂不可兑换”的到期提示是否足够公平。

### P1：透明度和技术一致性

- 按到期日分组展示积分，而不是把所有积分合并到最早日期。
- 明确非闰年 2 月 29 日生日规则。
- 增加升级、降档、积分到账和到期通知。
- 提供完整积分明细、到期日历和用户侧等级变更原因。
- 金额内部精度统一为分，明确积分取整规则。
- 建立会员规则版本、存量重算和影响预览。

### P2：权益与跨端治理

- 评估钻石档是否需要优先客服、预约顾问、抢先体验等可交付权益。
- 逐步收敛跨端礼品计价，避免不同子站各自计算扣分。
- 根据数据决定是否需要成长值；没有明确业务目标前，不额外增加一套成长值体系。
